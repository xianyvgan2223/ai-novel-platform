# 使用指南

三个角色先分清楚：

| 角色 | 是什么 | 干什么 |
| --- | --- | --- |
| **手机 App** | 你原来的 Flutter 应用 | 生产数据；汉堡菜单里有「数据同步」，设置里也有入口与「导出/导入数据库」 |
| **Web 服务** | `web/server-java`，一个 Spring Boot 进程 | 存放数据、提供接口、托管网页 |
| **浏览器** | Chrome / Edge 打开的那个页面 | 看数据、改数据、备份 |

**手机和 Web 的同步有两条路**：直接点同步（推荐），或者用 .db 文件来回搬（备用）。

> **每台设备各存一份，互不同步。**
> 服务端按设备分目录存放：A 手机的数据不会出现在 B 手机上，两台手机的"第 1 条会话"
> 即使主键相同也不会互相覆盖。网页右上角可以切换要看哪台设备的数据。
> 想让数据从一台手机到另一台？见 [五、多台设备怎么用](#五多台设备怎么用)。

## 一、启动服务

```powershell
cd web/server-java
.\mvnw.cmd spring-boot:run
```

也可以直接在 IDEA 里运行 `WebServerApplication`。

输出长这样，**记下「手机端的地址」那一行**：

```
本机访问:  http://localhost:3210
手机请填:  http://192.168.43.5:3210   ← 手机 App / 浏览器用这个

── USB 隧道（手机插着数据线即可，不看 Wi-Fi、不怕防火墙）──
默认会随服务自动建立；不想用可加 --app.usb-auto=false 关闭
手机端服务地址填:  http://127.0.0.1:3210
```

服务默认监听 `0.0.0.0`，所以同一局域网内的手机可以直接访问。

> **数据存放在 `web/server/data/`**：
>
> ```
> data/
>   devices/
>     phone-e3e655ac/      ← 这台手机自己的数据
>       deepseek.db            主库（对话 / 小说 / 角色扮演 / 跑团）
>       novel.db               小说游戏库
>       sync.db                这台的变更日志与行版本
>     phone-1bf2d708/      ← 另一台手机自己的数据
>     web-console/         ← 网页控制台自己的数据（上传 .db 默认落这里）
>   sync.db                ← 全局登记表：设备清单 / 待办请求 / 冲突留档
> ```
>
> **备份就是把整个 `data/` 目录拷走**（`-wal` / `-shm` 是临时文件，不用单独备份）。
> 停服务后整目录复制最稳妥。

### 想先随便点一点看看效果

把真实数据复制一份当演示库，再用它启动（不会碰你的真实数据）：

```powershell
Copy-Item -Recurse web/server/data web/server/data-demo2
cd web/server-java
$env:DATA_DIR='../server/data-demo2'
.\mvnw.cmd spring-boot:run
```

## 二、最稳的连法：USB 数据线（推荐）

手机插着数据线时，**用 USB 隧道**：手机访问 `http://127.0.0.1:3210` 就等于访问电脑上的服务。
它不看 Wi-Fi、不经过路由器、也不受 Windows 防火墙影响（走的是 USB 上的 adb 通道），
所以「热点换来换去导致地址变化」这类问题根本不会出现。

### 一次性准备（只做一次）

1. 手机开启**开发者选项 → USB 调试**（连上电脑时手机会弹「允许 USB 调试」，选允许）
2. 电脑上有 `adb`（Android SDK 的 platform-tools；装过 scrcpy 的话它目录里也自带一个）

### 每次使用（一条命令）

```powershell
# 启动同步服务：Java 版默认会自动建立 USB 隧道（手机插着数据线即可）
cd web/server-java
.\mvnw.cmd spring-boot:run
```

看到这一行就通了：

```
[usb] 设备 AQQB9X1526W02408：隧道已建立 → 手机可访问 http://127.0.0.1:3210
```

**手机 App 里服务地址填 `http://127.0.0.1:3210`**，点「测试连接」应出现「连接成功」。

### 这个守护会自己处理意外

| 情况 | 行为 |
| --- | --- |
| 手机拔掉再插上 | 自动重新建立隧道 |
| adb 服务重启 / 隧道被清掉 | 2 秒内自动重建 |
| 上次被强制关闭、隧道残留在手机上 | 下次启动时自动识别并清掉重建（避免手机连到一个已经没服务的端口） |
| 手机没插 | 什么都不做，不会误删已有的隧道 |
| 按 Ctrl+C 退出 | 顺手把隧道清掉 |

### 手机 App 这边不用配也能连

同步页顶部的「连接通道」面板会自己探测：隧道通了会显示绿色「**USB 隧道已就绪**」。
即使你没填地址，直接点同步也会按这个顺序自动找电脑：

```
上次用的地址 → USB 隧道(127.0.0.1) → 历史地址 → 热点网关 → 广播自报 → 扫描局域网
```

也就是说：**插上线 + 电脑上跑着 Java 服务（默认自动建隧道）+ 手机上点一下同步**，就能同步，全程不用抄 IP。

> 电脑上想自己确认隧道在不在：`adb reverse --list` 会打印 `usb tcp:3210 tcp:3210`。

## 三、Wi-Fi / 热点的连法（不用数据线时）

### 前提

- 手机和电脑连**同一个 Wi-Fi**，或者**电脑连手机的热点**
- 电脑上服务已经启动（第一步）

### 方式一：在电脑上点（推荐）

网页**右上角**有个「**同步手机**」按钮，点它就是一次**整库同步**：手机把整库变化上传，同时把电脑上改过的内容拉回手机。

1. 电脑上点「同步手机」
2. 按钮旁实时显示：`等待手机上确认…` → 手机上点「同意同步」后变成
   `手机已接收，正在同步…` → `上传（3/24）数据集 · 12 行` 加百分比
3. 完成后绿色提示「整库同步完成」，总览数据自动刷新

**手机要在弹窗里点「同意同步」才会执行**，不会在用户不知情时直接改数据；点「拒绝」则这次什么都不做，电脑端会提示「手机拒绝了本次同步」。手机 App 需要在前台，5 秒内会收到弹窗。

> 注意：轮询只在 App 前台运行。手机锁屏放着、App 被系统冻结时不会响应，
> 网页 120 秒后会提示「手机没有响应」。

### 方式二：在手机上点

1. 手机打开 App → 左上角 **☰ 汉堡菜单**（历史会话页）
2. 最底部有「**整库同步**」一栏，**点一下就直接同步整库数据**
3. 那一行会实时显示进度（`正在同步…`、`上传中（3/24）…`），完成后变成「上次同步 09-22 08:15」

### 地址怎么填

第一次用才需要填（USB 隧道的情况则固定填 `http://127.0.0.1:3210`）：

1. App → **设置** → 「**整库同步**」→ 点进去
2. 点「**自动找电脑**」，让它自己找；或把第一步记下的「手机请填」地址抄进「服务地址」
3. 点「**测试连接**」，看到「连接成功 · deepseekapp-web-sync …」就说明通了

**什么都不填也能用**：同步页点「自动找电脑」，会依次试
USB 隧道 → 上次的地址 → 历史地址 → 热点网关（192.168.43.1 / 192.168.42.1 / 192.168.137.1）
→ UDP 广播 → 扫整个网段。找到就自动记住，下次直接命中。

### 它到底做了什么

1. 先**拉取**：服务端上「**这台手机自己的槽位**」里被电脑改过的内容，会更新到手机（**增量**，只取上次之后的新变更）
2. 再**上传**：先在手机本地比对内容指纹，**只有改过的行才会发出去**（不是每次全传）
3. 手机上删掉的内容也会**同步删除服务端**的记录
4. **API Key 不在同步范围内**（既不上传也不会被覆盖），没必要把密钥送到网页上
5. 电脑主动发起时，手机会先弹窗问你「是否同意」，同意后才执行

进度是实时的：电脑网页上显示 `上传（3/24）数据集 · 12 行` 加百分比，手机汉堡菜单那一行同步显示。

> 升级后的**第一次同步仍会全传一遍**（手机上还没有指纹基线），之后就只传改动了。

同步是幂等的：两边内容一样时服务端会按内容哈希判重，不会重复写入、也不会把数据搞乱。
所以「想同步就点一下」完全没问题，多点几次不会出问题。

**每台手机只跟自己那一份数据打交道。** 服务端为每台设备单独保存一套库和一套变更日志：

```
手机 A ──push/pull──►  devices/phone-A/  ◄── 网页（切到 phone-A 时）
手机 B ──push/pull──►  devices/phone-B/  ◄── 网页（切到 phone-B 时）
```

两台设备之间**没有任何数据流动** —— 所以：
- 手机上删掉的东西不会牵连另一台手机
- 两台手机的同 ID 行不会互相覆盖（这也是以前最容易出问题的地方）
- 网页上的编辑只落到你当前选中的那台设备

### 注意事项

- 同步完成后建议**返回首页重新进入**，列表才会显示最新数据（页面上的列表不会自动刷新）
- 网页右上角「当前设备」决定了你在看谁的数据 —— **改数据前先确认切对了设备**
- 如果同一行被网页和手机都改过，**保留服务端（网页）的版本**，并把这次冲突记录在
  网页「同步与备份 → ④ 同步冲突记录」里（表里标了属于哪台设备）
- 第一次打开新版本 App 时会自动做一次数据库升级（只新增两张同步用的簿记表），
  **不会动任何对话或作品数据**

### 连不上怎么办

按顺序排查：

| 检查项 | 说明 |
| --- | --- |
| **先用 USB 试一次** | 插上数据线 + 电脑上跑着 Java 服务（默认会自动建 USB 隧道）+ 地址填 `http://127.0.0.1:3210`。这条路绕开了 Wi-Fi 和防火墙，能通说明手机与 App 都没问题，剩下的只是网络地址的事 |
| 地址填对了吗 | Wi-Fi 方式必须用「**手机请填**」那一行。`172.30.x`、`192.168.116.x`、`26.x` 这类是虚拟网卡（WSL / VMware / 加速器），手机连不上 |
| 手机和电脑同网段吗 | 电脑连手机热点时，电脑地址通常是 `192.168.43.x` 开头 |
| Windows 防火墙 | Wi-Fi 方式下的常见原因。用**管理员** PowerShell 执行一次即可放行：<br>`netsh advfirewall firewall add rule name="deepseekapp sync" dir=in action=allow protocol=TCP localport=3210` |
| 服务真的在跑吗 | 电脑浏览器打开 `http://localhost:3210` 能看到页面就说明服务正常，问题在网络 |
| USB 提示找不到 adb | 装 Android SDK 的 platform-tools，或指定路径：<br>`$env:ADB="D:\Android\platform-tools\adb.exe"; .\mvnw.cmd spring-boot:run` |
| USB 隧道显示已建但连不上 | 确认同步服务在同端口的 3210 上跑着；`adb reverse --list` 应打印 `usb tcp:3210 tcp:3210` |

> 提示：电脑连手机热点时，Windows 常把这个网络识别为「公用网络」，防火墙会更严格。
> 上面那条命令就是针对这种情况的。**不想折腾防火墙就直接用 USB 隧道。**

## 四、用文件搬运（备用方案）

网络不方便时，或者只想单向搬一次时用这条。**App 不需要任何同步配置**。

### 手机 → Web

1. **手机**：设置 → 「**导出数据库**」→ 得到 `deepseek_backup.db`
2. **传到电脑**：微信文件传输助手 / USB / 网盘都行
3. **网页**：右上角把「**当前设备**」切到你想放进哪台设备（或 Web 控制台）→
   左侧「同步与备份」→「① 导入 App 数据」→ 目标库选 `deepseek.db`、方式选**合并** → 选择文件
4. 导入只写进**当前选中的那台设备**，其它设备一点不受影响

### Web → 手机

1. **网页**：右上角切到要导出的那台设备 →「同步与备份」→「② 导出回手机」→ 下载 `.db`
   （不是 Web 控制台时，文件名会带设备号，例如 `deepseek_phone-e3e655ac_web-2026-10-13-004740.db`）
2. 传手机 → App 设置 →「导入数据库」→ 重启 App

### ⚠️ 这条路的三个坑

**坑 1：API Key 会丢。** 导出时「清空 API Key」开关**默认是开的**，导回手机后 App 会失去配置。
→ 导出前把它**关掉**（显示成「保留 API Key」）。只有要把文件发给别人才需要开。

**坑 2：App 的导入是「全量覆盖」。** 官方提示原文是"导入将覆盖当前所有数据"。
→ 顺序必须是：**手机导出 → 网页改 → 立刻导回手机**。别在导出之后又在手机上聊，那些新对话会被覆盖。

**坑 3：`novel.db`（小说游戏模块）导不进来。** App 的「导出数据库」只导出 `deepseek.db`。
这个库只能用上面的**直接同步**。

## 五、多台设备怎么用

**一句话：每台设备的数据在服务端是分开的，网页右上角切到谁，就在看谁、改谁。**

右上角「当前设备」下拉框里会列出：

| 条目 | 含义 |
| --- | --- |
| `Web 控制台` | 网页自己的槽位。上传 `.db` 默认落这里，适合"先在电脑上整理，再导给手机" |
| `phone-xxxxxxxx` | 某台手机。手机第一次同步后自动出现，`行数` 就是它同步上来的数据量 |

### 让某台手机同步

- 顶栏「**同步手机**」：选中某台设备时只请求那一台；停在 `Web 控制台` 时任何前台手机都能领取
- 「同步与备份」页设备表里每行都有「**请求整库同步**」，精确指定
- 两种方式都会在手机上弹窗，点「同意同步」后才执行

### 把数据从 A 手机搬到 B 手机

两台设备之间**不会自动同步**，要搬就显式搬一次：

1. 右上角切到 **A** → 「同步与备份」→「② 导出回手机」→ 下载 `deepseek_phone-A_web-….db`
2. 右上角切到 **B** → 「① 导入 App 数据」→ 方式选**合并** → 上传刚下载的文件
3. B 手机上点一次同步，数据就进 B 了

### 删掉某台设备在服务端的数据

设备表里那一行点「**删除数据**」，或在右上角下拉框里点垃圾桶图标。

- 删除的是**服务端**为它保存的目录（`data/devices/<设备号>/`）
- **手机本地数据不受影响**，手机下次同步会重新推一份上来
- Web 控制台的槽位不能删

### 从旧版本升级上来（v1 → v2）

旧版本把**所有设备的数据混在** `data/deepseek.db` / `data/novel.db` 里。升级后：

| 情况 | 服务端行为 |
| --- | --- |
| 登记表里**没有**设备（全新装） | 自动把旧库复制进 `data/devices/web-console/`，原文件改名 `*.legacy-bak` 留档 |
| 登记表里**已有**设备（用过同步） | **不动**旧文件，启动时会提示。因为分不清混库属于哪台手机，不猜 |

第二种情况想拿回旧数据：网页「同步与备份」页顶部会有黄色提示，选中目标设备后
把那个 `.db` 当普通文件「导入」一次即可（或直接删掉 `data/sync.db` 后重启，让它走自动搬迁）。

📌 **手机端不需要做任何事**：手机本地库才是它自己的权威数据，升级后第一次同步会把本机
全部数据重新推上来（进它自己的新槽位），网页面板里重新就有数据了。

## 六、在网页上能做什么

| 页面 | 能做什么 |
| --- | --- |
| **总览** | 各模块数据量、同步服务状态、当前设备与设备数量、每张表的行数与最近变更时间。点任意一行跳到该表 |
| **对话会话** | 按标题/末条消息/摘要搜索，双击一行看完整对话 |
| **会话详情** | 阅读完整对话，AI 回复渲染 Markdown，思考过程可展开，联网搜索来源可点开 |
| **数据浏览** | **最有用的一页**：24 张表全部可浏览、搜索、排序、编辑、新增、删除 |
| **同步与备份** | 导入导出、当前设备、设备清单（行数/水位/冲突）、冲突记录 |

以上页面显示的都是**右上角当前选中那台设备**的数据。

几个典型用法：

- **批量改小说章节**：数据浏览 → 选「写小说 · 章节」→ 找到章节 → 编辑 → 保存
- **导出某段内容**：会话详情里选文字复制；或数据浏览双击该行 → 「复制 JSON」
- **清理数据**：数据浏览里删除（删会话会**连带删除**它的全部消息，这是表结构决定的）
- **查设定**：数据浏览 → 角色扮演各表，看世界书条目与角色记忆

## 七、日常怎么用最省心

- **平时**：正常用手机 App，想在电脑上整理时点一次「数据同步」
- **整理完**：再点一次同步，或在网页上直接改完即可（网页的改动下次同步会拉到那台手机）
- **换电脑 / 重装**：把 `web/server/data/` 整个目录拷回去就行；手机上「重置同步状态」后重新同步会重新比对一遍
- **多台手机**：各自同步各自的，互不干扰；要合并数据就按第六节手动搬一次

## 八、让别人（或手机浏览器）也能访问

同一 Wi-Fi 下的手机/平板用「手机请填」的地址就能打开网页界面。

⚠️ 一旦要跨网络访问（端口映射、内网穿透、放到公网服务器），**必须开启鉴权**：

```powershell
cd web/server-java
$env:API_TOKEN='一串足够长的随机字符串'
.\mvnw.cmd spring-boot:run
```

想长期生效，可以把令牌写进 `application.yml` 的 `app.api-token`，或用系统环境变量 `API_TOKEN`。

然后在手机 App 的「数据同步 → 高级选项 → 访问令牌」里填同一个值；
前端网页则在 `web/app/.env.local` 里填 `VITE_API_TOKEN` 并重新构建。

否则任何人都能读写你的全部数据 —— 包括**每一台设备**的数据。

## 九、常见问题

| 现象 | 原因 / 解决办法 |
| --- | --- |
| 手机「测试连接」失败 | 见第二节的排查表（八成是防火墙或填了虚拟网卡地址） |
| 网页顶部红色「无法连接同步服务」 | 服务端没启动。`cd web/server-java` 后 `.\mvnw.cmd spring-boot:run`，再点右上角刷新 |
| 打开是一片 0，没有任何数据 | 当前设备是空的。右上角切到有数据的那台设备；或走第二节同步一次；或按第一节复制一份 data 当演示库 |
| 切到某台设备后什么都看不到 | 每台设备的数据是独立的，那台还没同步过。让它同步一次即可 |
| 「设备不存在：xxx」 | 设备号写错了，或那台设备的数据被删了。接口错误信息里会列出可用设备 |
| 同步后手机上还是旧数据 | 返回首页重新进入页面（列表不会自动刷新） |
| 网页上改了数据，手机没变 | 确认右上角当前设备就是那台手机（改错设备了），然后手机点一次同步 |
| 同步很慢 | 数据量大时第一次同步会久一些。之后只有变化的部分需要传 |
| 升级后网页里旧数据不见了 | 见第六节「从旧版本升级上来」，旧共享库需要手动导入一次 |
| 导入时提示「数据库版本 vXX 高于 Web 端支持的 vYY」 | App 升级了表结构但 Web 端还没跟上。按 `数据模型.md` 第 6 节更新 `schema.json` |
| 导出下载没反应 | 浏览器拦截了下载，允许该网站下载即可 |
| 端口 3210 被占用 | `$env:PORT='3211'; .\mvnw.cmd spring-boot:run`，手机端同步地址也要跟着改成 3211 |

## 十、实现细节在哪

想改同步行为（比如加上自动同步、后台定时同步），看这几个文件：

| 关注点 | 文件 |
| --- | --- |
| 哪些表参与同步 | `lib/features/sync/data/sync_targets.dart` |
| HTTP 请求与错误翻译 | `lib/features/sync/data/sync_client.dart` |
| **连接通道解析（USB 隧道优先）** | `lib/features/sync/data/address_resolver.dart` |
| 局域网扫描 / 广播自报 | `lib/features/sync/data/server_discovery.dart` |
| 同步流程编排 | `lib/features/sync/application/sync_service.dart` |
| 界面（含连接通道面板） | `lib/features/sync/presentation/sync_page.dart` |
| 协议说明 | [同步协议.md](同步协议.md) |
| 服务端设备隔离实现 | `web/server-java/.../sync/SyncStore.java`、`.../db/DatabaseManager.java` |
| 服务端可用地址探测 | `web/server-java/.../util/NetworkUtil.java`、`GET /api/net` |
| **USB 隧道守护** | `web/server-java/.../usb/AutoUsbTunnel.java`（默认随服务启动） |
| 设备解析中间件 | `web/server-java/.../web/DeviceContextFilter.java` |
| 前端设备切换 | `web/app/src/stores/device.ts`、`web/app/src/layouts/AppLayout.vue` |

自检：

```powershell
# 服务端：启动后访问 http://localhost:3210/api/health 应返回 ok=true
cd web/server-java
.\mvnw.cmd spring-boot:run

# 手机端连接通道（电脑上跑着服务时才会执行「能连上」那两组的断言）
flutter test test/sync_channel_test.dart
```
